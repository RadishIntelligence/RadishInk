# 11 月 23 日手机写作与公众号草稿验收

本日先用合成稿复现并修复站点 PNG 阻断 ZIP 导出的问题，随后在公网版复验。晚间使用 macOS Chrome 核对了含四张本地 PNG 的文章包，并在真实公众号后台观察了同稿通过本机富文本剪贴板粘贴后的效果。手机真机尚待验收。

## 公网复现

- 验收站点为 [ink.radishx.com](https://ink.radishx.com/)。Vercel 按域名回读为 `READY`，Git 提交为 `0fb411a2ccf14b9597cb1748aa9ee42a759774d4`。匿名访问 PWA 的 192 像素图标、写作插画和 Mac 代码栏装饰图均返回 HTTP 200，类型分别为 PNG、SVG、SVG，响应与仓库原文件逐字节一致。
- 在 macOS 27.0.1 的独立 Chromium 153.0.8010.12 会话使用 390 × 844 触屏视口、默认主题，表格自动换行与外链转脚注均沿用默认关闭。通过移动文件菜单导入[完整合成稿](../deployment/wechat-acceptance-sample.md)，输入 `RI-1123 手机写作验收。`，再通过“选择图片”插入一份本地 PNG。
- 保存、刷新后能读回改动、文末标记和手选的 PNG。预览中样例自带的 SVG 可见，样例自带的 PNG 显示“资源缺失或路径不支持”。选择导出 ZIP 后再次复现失败，提示为“文章包未导出：本地资源缺失或路径不支持：/pwa/icon-192.png”。

## 本地修复与同稿回归

预览、ZIP 检查和复制共用图片来源判定。原规则认识两张站点 SVG，遗漏了样例使用的 PNG。将该 PNG 的确切路径加入站点图片清单，其他未知相对路径继续按文章资源检查。[图片存储契约](../development/article-storage-contract.md)

1. 使用修复后的本地 Web 生产构建重复上述操作。刷新后站点 PNG、SVG 和手选的 PNG 均可解码。导出并解包，核对新增的编辑标记和一条图片引用后，正文与完整样例一致。包中手选原图为 3,613 字节，SHA-256 为 `562b119a227a38a5c850994629ed32c5522e664dac73ece3018250b0f152c9cc`，与输入文件逐字节一致。
2. 在另一份空桌面浏览器会话导入同一 ZIP，刷新后能读回编辑标记、文末 `RI-END` 和三张图片。保留包内图片引用时，公众号复制提示有一张本地图片并停止。
3. 在导入副本中只移除包内图片引用，再执行“复制到公众号”。从浏览器剪贴板读回的 HTML 包含编辑标记、文末、两张表格、四个内联 SVG 和一个内嵌 PNG。两张站点图片的地址均指向当前测试源，图片地址中没有 Blob URL。

修复前，新增的预览与 ZIP 断言均失败。修复后 `mise exec -- pnpm test:web` 通过 core 64 项和 Web 803 项测试。`lint:web` 通过，有 12 条既有警告。`build:web` 通过，保留动态导入和大块体积提示。本地验收使用临时回环服务，结束后释放端口。

## 公网复验与真实公众号草稿

- **公网合成稿。** Vercel 确认验收域名运行 `29a4e01`。复验覆盖图片拖入、保存刷新、ZIP 导出和独立浏览器会话回导，包内两张原图与输入逐字节一致。[部署详情](https://vercel.com/dabailuobo/radish-ink/8gEQjs84rXvfQpzmqjx4KavLqyx9)
- **公众号草稿。** 在 macOS 剪贴板中写入带四张内嵌 PNG 的 HTML，由作者粘贴到微信公众平台。后台显示已保存，截图可见正文、加粗、小标题、首图、示意图和图注。另两张图由作者目视确认。该 HTML 由本机单独生成。作者随后反馈重开后文章仍在。四张图的位置和图中文字的可读性留到手机预览时一起核对。
- **线上按钮。** 作者在 RadishInk 默认主题导入同一篇文章的 ZIP。编辑区显示文章资源引用，预览能显示对应示意图。点击“复制到公众号”后，页面提示含 4 张本地图片、尚未验证公众号转存、本次未复制，并给出解包手工插图或使用可访问图片链接的办法。本轮在提示处结束。

## 桌面预览与草稿的三处差异

作者对照 RadishInk 默认主题预览与微信公众平台桌面草稿，指出以下三处差异，其余显示可接受。草稿使用本机单独生成的 HTML。另在隔离 Chromium 中用一份合成 Markdown 对照本地生产构建的预览与“复制到公众号”写出的富文本。样例使用站点 PNG、图片替代文本、独立斜体图注、带页码片段的外链和二级标题，沿用默认主题并关闭外链转脚注。

| 项目     | 桌面草稿及其输入                                                                                       | RadishInk 同稿预览与剪贴板                                            |
| -------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| 图注     | 单独生成的 HTML 只将作者图注显示为 13 px 灰色正体，另保留图片的替代文本属性。                          | 图片替代文本生成 14 px 灰色可见图注，后续 Markdown 斜体段落另行保留。 |
| 论文链接 | 写入剪贴板时包含链接地址、页码片段、颜色和下划线。草稿截图中引文与正文同色，未见下划线，能否打开待验。 | 剪贴板保留了预览中的目标地址和页码片段，以及绿色和 1 px 下边框。      |
| 二级标题 | 单独生成的 HTML 指定了 3 px 棕色左边框，草稿中可以看到左竖线。                                         | 两端均为 22 px、字重 700 和 2 px 下边框。                             |

图注和标题的差异可追溯到两份 HTML 的输入样式。这组截图来自桌面编辑器，手机阅读效果另验。作者随后确定，后续稿件在文末放可复制的完整静态网址；以此作为后续链接验收目标。[公众号稿件的参考资料](../deployment/wechat-acceptance.md#公众号稿件的参考资料)

### 文末静态网址的本地复验

用合成稿在隔离 Chromium 的本地生产构建中测试了默认预览和“复制到公众号”。同一 PDF 引用三次，其中两次指向同一页。两端均显示三个引用编号和两个独立的网址段落。回读剪贴板 HTML 后，地址保留查询参数中的 `&` 和 `#page=` 页码，参考资料标题随正文写入，无可点击的网页链接。`mise exec -- pnpm validate:web` 通过，含 core 64 项、Web 808 项测试，Lint 有 12 条既有警告。

## 长公式独立排版

作者指出，一条以 Markdown 粗体书写的长等式在公众号正文中断在乘号后。将该式改写为独立的 `$$` 公式块，前后说明各成一段。在本地生产构建导入文章包后，原有四张插图均能解码，公式在 256 px 的可用宽度内完整显示。另用只含公式和文字的小样测试“复制到公众号”，回读剪贴板可见居中的块级 SVG，句中的变量仍为行内 SVG。为现有公众号草稿另行导出了单张公式 PNG。手机微信对这版公式的显示效果待验。
